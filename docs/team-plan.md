## 3. Организация работы

Работа над проектом ведётся через GitHub.

Для управления задачами используется GitHub Issues. Каждая задача должна иметь описание, ответственного исполнителя и критерии приёмки.

Для выполнения задач участники создают отдельные короткоживущие ветки. Изменения передаются в основную ветку `main` через Pull Request.

Перед объединением Pull Request необходимо получить как минимум одно одобрение и успешно пройти обязательные проверки.

## 5. Порядок взаимодействия

1. Задачи фиксируются в GitHub Issues.
2. Ответственный участник выполняет задачу в отдельной ветке.
3. Результат фиксируется коммитами с использованием Conventional Commits.
4. Для передачи изменений создаётся Pull Request.
5. Другой участник команды проводит ревью.
6. Автор отвечает на замечания и вносит необходимые исправления.
7. После одобрения и успешного прохождения проверок изменения объединяются с `main`.

## 6. Контроль результатов

Результаты работы проверяются по критериям приёмки соответствующих Issues.

Завершённая задача должна иметь проверяемый результат, актуальную документацию и, если применимо, успешно пройденные тесты.
