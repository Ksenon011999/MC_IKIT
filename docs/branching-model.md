# Модель ветвления

## Выбор
Упрощённый Flow с единственной долгосрочной веткой `main`.

## Обоснование
- Команда небольшая, учебный проект — Git Flow с develop/release избыточен.
- Короткоживущие ветки от main уменьшают конфликты.
- Обязательный PR + ревью + CI дают контроль качества без накладных расходов.

## Правила
- `main` защищена: прямые пуши запрещены, нужен ≥1 approve, нужны зелёные checks.
- Ветки: `feature/<id>-<slug>`, `docs/<id>-<slug>`, `chore/<id>-<slug>`.
- Коммиты: Conventional Commits с ID задачи: `feat(#12): add health-check`.
- Слияние: merge commit.
